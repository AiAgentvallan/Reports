⛔ Why these scenarios are blocked
When a renter replies with a word like "absolutely", "ok", or "correct", the backend function do_response/2 in alert.ex tries to match the reply against @valid_claim_accept_responses and @valid_claim_deny_responses. If no match is found, the word falls into the true → :claim_unparseable catch-all. This sets alert.status = :bad_response and sends a help SMS to the renter instead of clearing the incident.

The renter intended to say YES but the system did not understand — the incident stays open and the renter is confused. Fix: add the 15 missing single words to @valid_claim_accept_responses. The 4 multi-word phrases additionally need a regex algorithm change.

⚠️ 4 multi-word phrases need a separate algorithm change — the current regex ~r/^\s*[[:punct:]]*\s*(keyword)\s*[[:punct:]]*\s*$/i only matches a single keyword token. Phrases with spaces ("of course", "no problem", "sounds good", "for sure") will never match. A new matching path is needed (e.g. normalize spaces, or extend the regex to allow internal spaces). These are the hardest 4 words to fix.
