Section 1

What is this? (Plain English)

No jargon. Read this first regardless of your background.

🏦
Think of it like a bank statement — but for your storage facility security
Non-technical explanation

Right now, when a Storage Defender customer pays their monthly subscription, they get security monitoring — but they don't see a clear summary of what that monitoring actually did for them that month. It's like paying for insurance but never knowing what claims it saved you from.

This idea changes that. Every month, each facility manager receives a personalised report that says: "This month, your Smart Units detected 23 motion events. 18 were confirmed by your tenants as legitimate access — your team only needed to respond to 4. Your temperature sensors caught a climate issue in Zone 3 before any damage occurred. Your 60 Smart Units currently cover 60% of your facility — 40 units are still unmonitored."

The report is written in plain sentences by an AI (Claude), not just raw numbers in a table. It reads like a letter from your security manager — friendly, clear, and focused on business value.

For the CS and Sales team, every facility gets a score showing how many unmonitored units could benefit from Smart Units next. This turns a passive subscription into an active upsell conversation backed by real data.

👔
Why this grows revenue
Business case — 60 seconds

Customers cancel subscriptions when they don't see value. By making the value visible, measurable, and personal, we reduce churn. A customer who just read "Your 60 Smart Units handled 78% of alerts automatically — your staff only needed to respond to 4 events this month" is not cancelling their $720/month subscription.

The CS team can also use the expansion score in the report to say: "You have 40 unmonitored units — adding Smart Units to those at $12/device = $480/month for 100% facility coverage." That's a direct upsell conversation backed by real data — not a cold pitch.

Section 3

Step-by-Step Build Plan

7 concrete steps. Each one is a discrete unit of work that can be built, tested, and merged independently.

1
Data Layer
Write BigQuery SQL queries — pull monthly metrics per facility

Write 5–6 BigQuery SQL queries that pull the data we need for the report. These run on the 1st of each month and return one row per facility.

Metrics to calculate:

-- 1. Total incidents this month per facility SELECT facility_id, COUNT(*) AS total_incidents, COUNTIF(status = 'resolved_by_tenant') AS self_cleared, COUNTIF(status = 'escalated') AS escalated, COUNTIF(sensor_type = 'motion') AS motion_events, COUNTIF(sensor_type = 'door') AS door_events, COUNTIF(sensor_type IN ('temperature','humidity')) AS env_alerts FROM `tod_backoffice.incidents` WHERE created_at BETWEEN DATE_TRUNC(CURRENT_DATE(), MONTH) AND LAST_DAY(CURRENT_DATE(), MONTH) GROUP BY facility_id; -- 2. Facility coverage % and subscription value -- Subscription revenue = active smart units × $12/month (flat fee per device) -- Coverage % = smart_unit_count / total_unit_count × 100 -- Expansion opportunity = (total_units - smart_units) × 12 → upsell revenue for SD SELECT facility_id, smart_unit_count, total_unit_count, ROUND(smart_unit_count / total_unit_count * 100, 1) AS coverage_pct, smart_unit_count * 12 AS monthly_subscription_usd, (total_unit_count - smart_unit_count) * 12 AS expansion_opportunity_usd FROM `tod_backoffice.facilities_summary` WHERE facility_id = @facility_id; -- 3. Month-over-month delta (compare to same query last month) -- 4. Smart units count vs total units → expansion opportunity score -- 5. Avg incident response time (time to tenant SMS reply)
2
Compute Layer
Build the Metrics Engine — a Cloud Run service that runs on a schedule

A lightweight Node.js (or Python) service deployed on Google Cloud Run, triggered by Cloud Scheduler on the 1st of each month at 6am UTC.

It loops through every active facility, runs the BigQuery queries, assembles a structured JSON payload, and hands it off to the Claude API call.

// metrics-engine/index.js (simplified) const facilities = await getActiveFacilities(); // from tod_backoffice for (const facility of facilities) { const metrics = await runBigQueryMetrics(facility.id, lastMonth); const payload = { facility_name: facility.name, month: "April 2026", total_incidents: metrics.total_incidents, // e.g. 23 self_cleared: metrics.self_cleared, // e.g. 18 escalated: metrics.escalated, // e.g. 4 env_alerts: metrics.env_alerts, // e.g. 2 coverage_pct: metrics.coverage_pct, // e.g. 60% monthly_sub_usd: metrics.smart_unit_count * 12, // e.g. $720 (60 devices × $12) expansion_usd: (metrics.total_unit_count - metrics.smart_unit_count) * 12, // e.g. $480 upsell opportunity mom_change: metrics.mom_delta_pct, // e.g. +12% smart_units: metrics.smart_unit_count, // e.g. 60 total_units: metrics.total_unit_count, // e.g. 100 expansion_score: metrics.expansion_score // e.g. 72/100 }; const report = await generateWithClaude(payload); await buildAndDeliverReport(facility, report); }
3
AI Layer — Most Important Step
Integrate Claude API to write the narrative section

We call the Claude Sonnet API with the metrics JSON and a system prompt. Claude converts the numbers into a well-written paragraph that sounds like it came from a professional security manager — not a data export.

We use prompt caching — the system prompt is the same for every facility, so Anthropic caches it and we only pay for input tokens once. Saves ~70% on API costs when generating reports for hundreds of facilities.

// claude-integration.js const Anthropic = require('@anthropic-ai/sdk'); const client = new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY }); async function generateWithClaude(metrics) { const response = await client.messages.create({ model: "claude-sonnet-4-6", max_tokens: 600, system: [ { type: "text", text: `You are a professional security analyst at Storage Defender. Write a concise, friendly monthly security summary for a self-storage facility manager. Tone: professional but warm. 3–4 short paragraphs. Highlight wins (self-resolution rate, response speed), flag concerns, and end with one specific expansion action citing unmonitored units and the exact additional monthly subscription cost to cover them. Never invent dollar savings figures — only use the numbers provided.`, // ↓ This enables prompt caching — saves cost on 100s of facilities cache_control: { type: "ephemeral" } } ], messages: [{ role: "user", content: `Generate the monthly value report for this facility: ${JSON.stringify(metrics, null, 2)}` }] }); return response.content[0].text; }
💡

Why Claude Sonnet specifically? It's the best balance of quality, speed, and cost for this use case. Opus would be overkill for a structured report; Haiku might produce less fluent prose. Sonnet writes at a near-human level and processes 100 facility reports in ~4 minutes at minimal cost (~$0.02 per report).

4
Report Builder
Build the HTML report template + convert to PDF

Combine the metrics JSON + Claude narrative into a branded HTML template, then convert to PDF using Puppeteer (headless Chrome). The PDF is stored in Google Cloud Storage and a signed URL is generated for delivery.

The template includes: SD logo + branding, 4 KPI cards (total events, self-resolution rate, facility coverage %, expansion opportunity), Claude's narrative paragraph, month-over-month trend bar, and a CTA button to upgrade smart unit count.

// report-builder.js async function buildPDF(facility, metrics, claudeNarrative) { const html = renderTemplate({ facilityName: facility.name, month: "April 2026", kpis: { totalIncidents: metrics.total_incidents, coveragePct: `${metrics.coverage_pct}%`, selfResolutionRate: `${metrics.self_cleared_pct}%`, expansionOpportunity: `$${metrics.expansion_usd}/mo`, expansionScore: metrics.expansion_score }, narrative: claudeNarrative, momTrend: metrics.mom_change }); const browser = await puppeteer.launch(); const page = await browser.newPage(); await page.setContent(html, { waitUntil: 'networkidle0' }); const pdf = await page.pdf({ format: 'A4', printBackground: true }); await browser.close(); return uploadToGCS(`reports/${facility.id}/${month}.pdf`, pdf); }
5
Delivery Layer
Send the report — email + in-app notification

Two delivery channels for the pilot:

1. Email — Send via SendGrid (or Postmark) to the facility manager's registered email. Attach the PDF or include a "View Report" button linking to the GCS signed URL. Subject: "Your April Security Report — Riverside Storage".

2. In-app notification — Drop a notification in the Customer UI notification center with a link to the PDF. This is the path of least resistance for the pilot since the notification system already exists in SD.

// delivery.js await sendgrid.send({ to: facility.manager_email, from: 'reports@storage-defender.com', subject: `Your ${month} Security Report — ${facility.name}`, html: emailTemplate({ facilityName, month, pdfUrl, topStat }), attachments: [{ content: pdfBase64, filename: `SD_Report_${month}.pdf` }] }); // Also push in-app via BackOffice API await backofficeApi.createNotification({ facilityId: facility.id, type: 'monthly_report', title: `Your ${month} Security Report is ready`, link: pdfUrl });
6
CS Dashboard
Build a CS team view — upsell opportunity feed

A simple internal dashboard (or Looker Studio page) that shows the CS team all facilities ranked by their Expansion Score — how many unmonitored units are adjacent to high-incident zones.

Each row shows: facility name, current smart unit count, expansion opportunity (# units), and a "Send personalised upsell email" button that drafts a message using Claude with the facility's specific data pre-filled.

📊

For the pilot (30 days) — a simple Looker Studio dashboard connected to BigQuery is enough. No new UI development needed. Estimated setup time: 2 hours once the BigQuery data is ready.

7
Testing & Monitoring
Test, validate, and monitor the pipeline end-to-end

Before sending to all facilities, run the pipeline against 3–5 pilot facilities and have the CS team review the generated reports manually. Check: Are the metrics accurate? Does Claude's narrative make sense? Is the formatting clean on PDF?

Set up Cloud Logging alerts for failures in the pipeline (BigQuery query fail, Claude API error, email bounce). The job should send a Slack alert to the engineering channel if any step fails.

⚠️

Key validation: Verify smart_unit_count and total_unit_count are accurate per facility before the first live run — these drive the coverage % and expansion opportunity figures that customers see. Cross-check against tod_backoffice device records.

Section 4

Claude AI — Deep Dive

Exactly how we use the Anthropic Claude API, which model, why, and the full prompt strategy.

🤖

Claude Sonnet 4.6 — Anthropic API

Model ID: claude-sonnet-4-6  |  SDK: @anthropic-ai/sdk  |  Prompt caching enabled
Why Claude (not GPT / Gemini)?
  • Best-in-class at following structured instructions and writing in a specific tone
  • Prompt caching reduces cost by ~70% when same system prompt is reused across hundreds of facility reports
  • SD already has the Claude Code CLI — same vendor, easier procurement
  • Anthropic's Claude 4.x models have Aug 2025 knowledge cutoff — no staleness issues for this task
What Claude Does in This Flow
  • Receives the metrics JSON as user message
  • System prompt defines tone (professional, warm, concise)
  • Writes 3–4 paragraphs: summary, wins, concerns, expansion CTA
  • Always ends with coverage % and upsell expansion opportunity ($12 × unmonitored units)
  • Does NOT make up numbers — all figures come from the JSON input
Cost Estimate (per month)
  • ~200 facilities × ~600 output tokens = 120,000 tokens/month
  • Input tokens cached after first call (~50 tokens actual per facility)
  • Estimated cost: ~$4–6 USD per month for entire fleet
  • Scales linearly — 2,000 facilities ≈ $40–60/month
  • Negligible vs subscription revenue impact
Prompt Caching Strategy
  • System prompt is identical for every facility report
  • Mark system prompt with cache_control: ephemeral
  • First call: full input token cost
  • Subsequent calls (same hour): cached — 90% cheaper
  • Cache TTL: 5 minutes — process all facilities in one batch run

Section 7

AI Tool Options

We recommend Claude Sonnet, but here is how the alternatives compare.

⭐ Recommended
🤖

Claude Sonnet 4.6

Anthropic API — best fit for structured narrative generation from JSON data.

  • Prompt caching = 70% cost saving
  • Excellent at following tone instructions
  • SD already uses Claude Code — same account
  • ~$0.02 per report
  • Easy to fine-tune via system prompt
🟢

OpenAI GPT-4o

Good alternative if the team is more familiar with OpenAI SDK.

  • No prompt caching → higher cost at scale
  • ~$0.05 per report (2.5× more expensive)
  • Would need a new vendor account
  • Similar quality output for this task
  • Not recommended for SD given existing Claude usage
🔵

Google Gemini 1.5

Keeps everything within GCP — no external API vendor.

  • Native GCP integration (Vertex AI)
  • Free tier available for pilot
  • Slightly weaker narrative quality vs Claude
  • More setup complexity via Vertex AI
  • Good backup option if Anthropic access is delayed
