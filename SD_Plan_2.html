AI Smart Unit Gap Detector

Section 1

What is this? (Plain English)

No jargon. Read this first regardless of your background.

🔦
Think of it like a security torch revealing blind spots in a dark room
Non-technical explanation

Imagine a self-storage facility with 100 units. 60 of those units have Smart Units (SD sensors) installed. The other 40 do not. Right now, no one knows which of those 40 unmonitored units are actually the highest risk — they're invisible from a security standpoint.

This idea changes that. Every week, an AI engine scans the facility's activity data and asks: "Which unmonitored units are sitting right next to your busiest zones? Which ones have tenants who accessed outside facility hours? Which zones have the most incidents from the units that are monitored?" It then gives each unmonitored unit a risk score and shows the facility manager a heatmap: "These 12 units in Zone B are your biggest blind spots right now."

For the CS and Sales team, every facility gets a ranked list: "Riverside Storage has 40 unmonitored units. The top 12 have a high risk score. Upgrading those = $144/month in new subscriptions." That's a real, data-backed conversation — not a cold sales call.

👔
Why this grows revenue directly
Business case — 60 seconds

SD charges $12/device/month flat. Every unmonitored unit that gets a Smart Unit installed = +$12/month in new subscription revenue. This idea's entire purpose is to find those units and give the CS team and facility managers a compelling, data-driven reason to add them.

The data to do this already exists in tod_backoffice — incidents, zones, device records, PMS tenant data. No new sensors, no new data collection needed. The AI layer just connects the dots and surfaces the right units at the right time.

A facility with 40 unmonitored gap units represents $480/month in potential new subscription revenue (40 × $12). Across 200 facilities, even a 25% conversion rate = $24,000+/month in expansion revenue.

Section 3

Step-by-Step Build Plan

7 concrete steps. Each one is a discrete unit of work that can be built, tested, and merged independently.

1
Data Layer
Write BigQuery SQL — pull zone incident frequency, device coverage map, and PMS tenant data

The risk score for each unmonitored unit is built from 3 data sources already in tod_backoffice. Write separate queries for each, then join them in the scoring engine.

-- Query 1: Zone incident frequency (rolling 90 days) SELECT z.zone_id, z.facility_id, z.zone_name, COUNT(i.id) AS zone_incidents_90d, COUNTIF(i.status = 'escalated') AS escalated_count, COUNTIF(EXTRACT(HOUR FROM i.created_at) NOT BETWEEN 6 AND 22) AS after_hours_incidents FROM `tod_backoffice.zones` z LEFT JOIN `tod_backoffice.incidents` i ON i.zone_id = z.zone_id AND i.created_at >= DATE_SUB(CURRENT_DATE(), INTERVAL 90 DAY) GROUP BY z.zone_id, z.facility_id, z.zone_name; -- Query 2: Device coverage map — which units have Smart Units installed SELECT u.unit_id, u.unit_number, u.zone_id, u.facility_id, CASE WHEN d.unit_id IS NOT NULL THEN 'monitored' ELSE 'unmonitored' END AS coverage_status FROM `tod_backoffice.units` u LEFT JOIN `tod_backoffice.devices` d ON d.unit_id = u.unit_id AND d.status = 'active'; -- Query 3: Tenant data from PMS sync — flag new tenants (< 90 days) SELECT t.unit_id, t.move_in_date, DATE_DIFF(CURRENT_DATE(), t.move_in_date, DAY) AS days_as_tenant, CASE WHEN DATE_DIFF(CURRENT_DATE(), t.move_in_date, DAY) < 90 THEN 1 ELSE 0 END AS is_new_tenant FROM `tod_backoffice.tenants` t WHERE t.status = 'active'; -- Revenue calculation is simple: gap_units × $12 (flat device subscription) -- expansion_opportunity_usd = COUNT(unmonitored units) × 12
2
Scoring Engine
Build the Risk Scoring Engine — score each unmonitored unit 0–100

A lightweight scoring function that takes the 3 data sources above and assigns a risk_score (0–100) to each unmonitored unit. No machine learning required for the MVP — a weighted formula is enough and is fully explainable to facility managers.

// risk-scorer.js function calculateRiskScore(unit, zoneStats, tenantInfo) { let score = 0; // Factor 1: Zone incident frequency — 0 to 50 points // High-incident zone neighbours = higher risk for unmonitored units score += Math.min(50, (zoneStats.zone_incidents_90d || 0) * 2); // Factor 2: After-hours activity in the same zone — 0 to 30 points score += Math.min(30, (zoneStats.after_hours_incidents || 0) * 3); // Factor 3: New tenant flag (move-in < 90 days ago) — 0 or 20 points if (tenantInfo?.is_new_tenant) score += 20; return Math.min(100, Math.round(score)); } // Gap detection — find unmonitored units and rank by risk async function detectGaps(facilityId) { const unmonitored = await getUnmonitoredUnits(facilityId); const zoneStats = await getZoneStats(facilityId); const tenants = await getTenantData(facilityId); const gaps = unmonitored.map(unit => ({ unit_id: unit.unit_id, unit_number: unit.unit_number, zone_id: unit.zone_id, zone_name: unit.zone_name, risk_score: calculateRiskScore(unit, zoneStats[unit.zone_id], tenants[unit.unit_id]), subscription_usd: 12 // flat $12/device/month — no exceptions })); // Sort highest risk first return gaps.sort((a, b) => b.risk_score - a.risk_score); }
💡

Why not use ML? A rule-based weighted score is faster to build, easier to explain to a facility manager ("Zone B had 25 incidents last 90 days — that's why this unit scores 78"), and can be shipped in Week 2. ML scoring is a v2 enhancement once data volume grows.

3
AI Layer — Claude
Integrate Claude API to write personalised expansion recommendations

Once the gap list is scored, we hand the top gaps per facility to Claude Sonnet. Claude converts the JSON data into a clear, friendly recommendation that the facility manager can understand — and that the CS team can use as a ready-to-send email draft.

The key rule: Claude never invents numbers. All figures (gap count, zone names, $12/device) come from the JSON. Prompt caching means the system prompt is paid for once and reused across all facilities.

// claude-gap-advisor.js const Anthropic = require('@anthropic-ai/sdk'); const client = new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY }); async function generateGapRecommendation(facility, gaps) { const topGaps = gaps.slice(0, 10); // top 10 highest-risk gap units const payload = { facility_name: facility.name, current_smart_units: facility.smart_unit_count, total_units: facility.total_unit_count, current_subscription: facility.smart_unit_count * 12, // e.g. $720/mo total_gap_units: gaps.length, expansion_opp_usd: gaps.length * 12, // e.g. 40 gaps × $12 = $480/mo top_gap_units: topGaps, // ranked by risk_score highest_risk_zone: topGaps[0]?.zone_name }; const response = await client.messages.create({ model: "claude-sonnet-4-6", max_tokens: 450, system: [{ type: "text", text: `You are a security advisor at Storage Defender. Write a concise, friendly expansion recommendation for a facility manager. Identify which specific zones have the highest-risk unmonitored units. Always cite: current Smart Unit count, gap unit count, and the exact monthly subscription cost to close the gaps ($12 per Smart Unit device). Do not invent any numbers — use only what is provided in the data. Tone: helpful and specific, not pushy. 2–3 short paragraphs.`, cache_control: { type: "ephemeral" } // cached across all facilities }], messages: [{ role: "user", content: JSON.stringify(payload, null, 2) }] }); return response.content[0].text; }
4
Customer UI Layer
Build the facility heatmap — show gap units visually inside Customer UI

The most impactful deliverable for facility managers is a visual heatmap inside the Customer UI (Manage Facility / Smart Units section). Each unit in the facility is shown as a colour-coded cell: green = monitored, red = high-risk gap, orange = medium-risk gap, grey = low-risk unmonitored.

For the pilot, this can be a simple REST API endpoint that returns the scored gap data as JSON, rendered as an HTML/CSS grid in the existing Customer UI. No new UI framework needed — the BackOffice API already serves the Smart Units page.

// gap-api-endpoint.js — new BackOffice API endpoint // GET /api/facilities/:facilityId/gap-analysis router.get('/facilities/:facilityId/gap-analysis', async (req, res) => { const { facilityId } = req.params; // Read latest scored gaps from BigQuery output table const gaps = await bigquery .query(`SELECT * FROM tod_backoffice.gap_scores WHERE facility_id = @facilityId AND scored_at >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 24 HOUR) ORDER BY risk_score DESC`, { params: { facilityId } }); res.json({ facility_id: facilityId, total_gap_units: gaps.length, expansion_opp_usd: gaps.length * 12, // $12/device flat fee gap_units: gaps, generated_at: new Date().toISOString() }); });
⚡

Pilot shortcut: For the 45-day pilot, skip the Customer UI heatmap entirely and deliver the output via a Looker Studio dashboard + email only. The heatmap UI can be a v2 feature once the scoring engine is validated. This reduces engineering effort from ~3 weeks to ~4 days.

5
Delivery — Email to Facility Manager
Send personalised expansion email to each facility manager monthly

On the 1st of each month, send a personalised email to each facility manager whose gap analysis shows 5 or more high-risk gap units (risk_score > 70). Email includes Claude's written recommendation and a direct CTA to the Customer UI Smart Units page.

// delivery.js for (const facility of facilitiesWithHighRiskGaps) { const gaps = await detectGaps(facility.id); const narrative = await generateGapRecommendation(facility, gaps); const expansionUsd = gaps.length * 12; // $12/device — flat subscription await sendgrid.send({ to: facility.manager_email, from: 'insights@storage-defender.com', subject: `Coverage gap detected at ${facility.name} — ${gaps.length} unmonitored units`, html: gapEmailTemplate({ facility, gaps, narrative, expansionUsd }) }); // Also create in-app notification via BackOffice API await backofficeApi.createNotification({ facilityId: facility.id, type: 'gap_analysis', title: `${gaps.length} unmonitored high-risk units detected`, body: narrative }); }
6
CS Dashboard
Build CS upsell dashboard — ranked expansion opportunities across all accounts

A Looker Studio dashboard connected to the BigQuery gap_scores output table. Shows every facility ranked by expansion opportunity: gap count, top risk zone, expansion revenue ($12 × gaps), and a button to trigger the Claude-drafted upsell email.

📊

Fastest path to CS dashboard: BigQuery output table → Looker Studio. No new UI dev. Setup time: 3–4 hours once the scoring engine writes data to BigQuery. CS team can filter by region, risk level, or expansion opportunity size.

7
Testing & Monitoring
Test, validate, and monitor the scoring pipeline end-to-end

Before enabling for all facilities, run the scoring engine against 5–10 pilot facilities and have the CS team manually verify the output. Check: Are the highest-scored units actually in the most active zones? Do the zone names match? Are the device counts accurate?

Set up Cloud Logging alerts for scoring failures and send a Slack alert to the engineering channel on any pipeline error.

⚠️

Key validation: Cross-check the devices table against actual installed devices before the first run — stale or deprovisioned device records will make the coverage map inaccurate, which affects every risk score downstream.

Claude AI — Deep Dive

Exactly how Claude is used in this feature, what it generates, and why it fits here.

🤖

Claude Sonnet 4.6 — Anthropic API

Model ID: claude-sonnet-4-6  |  SDK: @anthropic-ai/sdk  |  Prompt caching enabled
What Claude Does Here
  • Takes the scored gap unit JSON as input
  • Identifies the highest-risk zones by name
  • Writes a 2–3 paragraph expansion recommendation
  • Cites exact $12/device cost — no invented figures
  • Also drafts a CS outreach email body ready to send
Why Not Just Show the Raw Data?
  • Facility managers are not data analysts — numbers alone don't drive action
  • A sentence like "Zone B has your 8 highest-risk blind spots at $96/month to cover" is more actionable than a score table
  • Claude adds context and a clear call to action that the raw JSON cannot
  • CS team gets a pre-written email — reduces their effort to 1 click
Cost Estimate (per month)
  • ~200 facilities × 1 report/month = 200 API calls
  • ~450 output tokens per facility
  • System prompt cached — paid once per batch run
  • Estimated: ~$4–6 USD/month for entire fleet
  • Scales to 2,000 facilities ≈ $40–60/month
Prompt Caching Strategy
  • System prompt is identical for all facilities
  • Mark with cache_control: ephemeral
  • Process all facilities in a single batch job run
  • First call: full input cost. Subsequent: ~90% cheaper
  • Cache TTL: 5 min — keep entire job under 5 minutes

"Your facility currently has 60 Smart Units covering 60% of Riverside Storage. Based on your facility's activity data over the last 90 days, we've identified 12 unmonitored units in Zone B and Zone C as your highest-risk blind spots — these zones had the most motion and door activity in the facility.

Adding Smart Units to just those 12 units would extend your coverage to 72% for an additional $144/month (12 units × $12/device). Full 100% coverage of all 100 units would be $480/month (40 remaining units × $12). Your current subscription is $720/month for 60 devices.

To upgrade coverage for Zone B and Zone C, reach out to your Storage Defender account manager or visit Smart Units in your portal."

Section 7

AI Tool Options

The risk scoring itself is rule-based (no AI needed). Claude is used only for narrative generation. Here is how the options compare.

⭐ Recommended
🤖

Claude Sonnet 4.6

Best fit for converting structured JSON data into clear, natural language recommendations.

  • Prompt caching = 70% cost saving across batch runs
  • Excellent instruction following — never invents numbers
  • SD already uses Claude Code — same vendor
  • ~$0.02 per facility narrative
  • Easiest to tune via system prompt
🟢

OpenAI GPT-4o

Viable alternative if team is more familiar with OpenAI SDK.

  • No prompt caching = higher cost at scale
  • ~$0.05 per facility (2.5× more expensive)
  • New vendor account needed
  • Similar quality for this specific task
  • Not recommended given existing Anthropic usage
📊

No AI (Rules Only)

Skip Claude entirely — generate templated text from the scored data.

  • Zero AI cost
  • Faster to build for pilot
  • Less natural language — reads like a template
  • Good fallback if Anthropic API key delayed
  • Can add Claude narrative in v2
