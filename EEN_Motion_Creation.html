② Automation Test Execution Flow
Step-by-step breakdown of what the Cucumber test does from trigger to assertion, for both Person Detection and Motion Detection scenarios.
1
api/eenWebhook.js

Trigger EEN Webhook Event

Publishes a RabbitMQ message directly to the amq.topic exchange using routing key sensor.een.camera.motion. The message mirrors the exact payload that eagle_eye_controller.ex would have produced after validating an EEN webhook. Stores the trigger timestamp (_triggeredAt) on the World context for cutoff calculation in the polling step.

2
EENPersonDetection.steps.js — Poll step

Poll GraphQL for Active Incident

Authenticates via GraphQL login mutation, then polls activeIncidents(type: "motion", limit: 20) every 5 seconds for up to 50 seconds (10 attempts). For each attempt, all returned incidents are logged with their age, status, and per-alert URL detection. The first incident with a startedAt timestamp ≥ the trigger cutoff (trigger time − 5s) is captured. Alerts are grouped by type (sms / slack / email) and stored on the context as _alertsByType.

2b
EENPersonDetection.steps.js — Validate SMS / Slack / Email

Validate Each Notification Channel Separately

Three independent steps run one after another — one for SMS, one for Slack, one for Email. Each step checks whether alerts of that type were created and whether a video URL is present in the alert body. The pass/fail/skip logic is identical for all three channels (see Section ③). If a URL is found, it is promoted to _videoURL for use in Step 3.

3
EENPersonDetection.steps.js — Navigate step

Navigate to Video URL

Opens _videoURL (the first URL extracted from any configured notification channel) in the Playwright browser using page.goto() with domcontentloaded wait, followed by a networkidle grace wait. Checks for 404 or error indicators in the DOM. On success, stores the final landed URL as _incidentPageURL.

4
EENPersonDetection.steps.js — Button step

Verify "View Video" Button Visible

Tries four Playwright selector strategies in order: button:has-text, a:has-text, [role="button"]:has-text, text=. If none match a visible element, a full-page screenshot is saved to test-results/ and the step fails. On success, prints the complete journey summary box to the console showing all channel results and key values.

📱 SMS Not Configured Phone / SMS responder — ⚠️ Skipped Add SMS responder + valid phone number in BackOffice
💬 Slack ✅ Active Slack responder dfndr.tiny.us/… ✅ Passed Already configured — working in QA

Why Slack in QA and not SMS? — SMS (Twilio) requires real phone numbers and incurs messaging costs. In QA, Slack webhooks are used instead as a free, non-disruptive alternative. Both channels carry the same video URL in the alert body. The automation treats them equally — only the type field in the GraphQL alert response differs ("slack" vs "sms").
